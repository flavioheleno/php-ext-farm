## 📥 Installation

### Download from Releases

1. Go to [Releases](../../releases)
2. Download the appropriate `.tar.gz` for your PHP version and platform
3. Extract and install:

```bash
# Extract the archive
tar -xzf redis-8.3-alpine-3.20.tar.gz

# Copy extension to PHP extension directory
cp redis.so $(php -r "echo ini_get('extension_dir');")

# Enable the extension
echo "extension=redis.so" >> $(php --ini | grep "Loaded Configuration" | cut -d: -f2 | tr -d ' ')

# Verify
php -m | grep redis
```

### Runtime Dependencies

Each archive contains a `metadata.json` with runtime dependencies. Install them before using the extension:

**Alpine:**
```bash
apk add --no-cache <runtime_deps>
```

**Debian:**
```bash
apt-get install -y <runtime_deps>
```

## 🔧 Local Building

### Prerequisites
- Docker
- jq
- bash

### Build a single extension

```bash
./scripts/build.sh <extension> <php_version> <platform> <platform_version> [extension_version]

# Examples:
./scripts/build.sh redis 8.3 alpine 3.20
./scripts/build.sh imagick 8.4 debian bookworm 3.7.0
```

### Check for new releases

```bash
./scripts/check-releases.sh
```

## ⚙️ Configuration

### extensions.json

The main configuration file defines:

- `php_versions`: List of PHP versions to build for
- `platforms`: Platform configurations (Alpine/Debian versions)
- `extensions`: Extension definitions including:
  - `type`: Extension type (pecl, git, etc.)
  - `pecl_name`: PECL package name
  - `track_url`: GitHub repository to track releases
  - `dependencies`: Build and runtime dependencies per platform

### Adding a New Extension

1. Add the extension to `extensions.json`:

```json
{
  "extensions": {
    "myext": {
      "type": "pecl",
      "pecl_name": "myext",
      "track_url": "https://github.com/owner/myext",
      "dependencies": {
        "alpine": {
          "build": ["autoconf", "gcc", "g++", "make"],
          "runtime": []
        },
        "debian": {
          "build": ["autoconf", "gcc", "g++", "make"],
          "runtime": []
        }
      }
    }
  }
}
```

2. Update the `build-all.yml` matrix to include the new extension.

## 🔄 Automation

### Daily Checks
- `check-releases.yml` runs daily to detect new extension releases
- Automatically triggers builds when new versions are found

### Weekly Builds
- `build-all.yml` runs weekly to rebuild all extensions with latest base images
- Ensures security updates from base images are included

### Manual Triggers
All workflows can be triggered manually:

```bash
# Build specific extension
gh workflow run build.yml -f extension=redis -f php_versions=8.3,8.4

# Create release
gh workflow run release.yml -f extension=redis -f extension_version=6.0.2

# Rebuild all
gh workflow run build-all.yml -f force_rebuild=true
```
